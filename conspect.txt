Архитектура проекта - разделение ответственности и отделения логики приложения от внешних деталей
1. Проще читать код
2. Изменения локализируются
3. Сервис проще тестировать отдельно от express
4. Проще добавлять новые endpoint-ы
5. Одна функция не пытается одновременно маршрутизировать, валидировать, искать данные и формировать ответ

Существует 4 слоя
1. Роутер - знает http метод и url, передает значение нужному handler-у
2. handler - получает req, res, читает query параметры и body, 
проверяет формат входных http данных, после чего вызывает сервис
3. Сервис - получает обычные значения или объекты, здесь находятся правила приложения
4. Репозиторий - работает с базой данных

JWT(Json web token) - видає підписаний токен
    (JWT зберігається у форматі base64)
завдяки якому можна перевірити термін дії тривалості сесії
Складається з:
Header.Payload.Signature
Header - описує мета данні токена
Payload - зберігає самі данні, складається з:
    Sub - суб'єкт токену
    IAT(Issued AT) - час створення токену
    Exp(Expiration Time) - час існування токену
Signature - Підпис, захисний механізм.
JWT зберігається у форматі base64
base64 - спосіб передачі байтів у вигляді тексту
Види токенів:
access token - короткотривалий пропуск для апі
refresh token - дозволяє отримати новий access token коли він закінчиться 
hash - це не зашифрованні данні які потрібно розшифрувати: 
    при в ході ми просто перевіряємо співпадіння паролю хешу

salt -  випадкові данні які argon2 використовує разом з паролем
argon2 - це сучасний та самий надійний алгоритм хеширування паролей
pepper - спільний секрет додатку який відповідає за ще один рівень захисту

cookie - це невелике значення яке сервер встановлює через set-cookie,
    браузер автоматично зберігає його та додає відповідні http запити

3 способи зберігання cookie:
    1.Json + LocalStorage - сервер віддає access token в json 
      frontend зберігає його та при кожному апі запиту додає 
      Authorization:Bearer - дійсний токен.
    2.httpOnly - сервер повертає set-cookie а браузер зберігає JWT
      і автоматично додає його до відповідних запитів у заголовку cookie.
    3.token in-memory - це токен записан у пам'яті додатку фронтенд
      отримує його з Json та тримає у змінній.
